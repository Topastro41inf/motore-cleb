# REGOLA — Pagina Documenti C.L.E.B.

**Stato:** regola operativa  
**Area:** portale pubblico / documentazione / sicurezza concettuale  
**Principio:** il sito deve rendere visibili le regole prima di attivare funzioni reali.

---

## 1. Scopo della pagina

La pagina Documenti serve a raccogliere e rendere navigabili le regole operative del sistema C.L.E.B.

Non è ancora una sezione legale definitiva.

Serve a:

```text
- mostrare le regole già scolpite
- distinguere prototipo, simulazione e sistema reale
- impedire confusione tra cliente, custode, albero, UV e FdA
- preparare il terreno per privacy, termini e consenso informato
```

---

## 2. Cosa può mostrare

La pagina può mostrare:

```text
- regole di accesso
- regole pallini / crediti personali
- confini dashboard cliente
- confini area Custode
- regola UV offline
- regola FdA separato
- note su privacy/termini futuri
```

---

## 3. Cosa non deve fare

La pagina Documenti non deve:

```text
- raccogliere dati personali
- attivare account reali
- attivare pagamenti
- salvare consensi reali
- sostituire documenti legali definitivi
- modificare MotoreCleb.jsx
- inglobare UV o FdA reali nel portale
```

---

## 4. Regola madre

```text
Prima chiarezza.
Poi validazione.
Poi backend.
Poi dati reali.
```

---

## 5. Confine C.L.E.B. / UV / FdA

```text
C.L.E.B. coordina.
UV opera offline.
FdA opera separato.
Il sito mostra, orienta e prepara.
Non sostituisce i sistemi vivi.
```

---

## 6. Lingua per l’utente

La pagina deve usare linguaggio semplice.

Il cliente non deve leggere:

```text
- formule tecniche
- algoritmi interni
- dettagli amministrativi
- meccaniche riservate al Custode
```

Il cliente deve capire:

```text
- cosa sta guardando
- cosa è già attivo
- cosa è simulato
- cosa arriverà dopo
- quali confini proteggono il sistema
```

---

## 7. Sigillo

```text
I documenti non sono burocrazia.
Sono le mura del tempio.
```
